# 前后端统一开发工具（uni-dev）设计

> 需求源：`docs/prd/uni-dev.md`。本文是经脑暴确认后的设计方案，实现计划另出。
> 关键决策均已在脑暴中与需求方逐条确认（D1–D6）。

## 1. 背景与目标

`@react-antd-module/cli`（ram）目前只覆盖前端模块工程（dev/build/info/merge）。
oj（only-js，Rust 内嵌 V8 的 JS/TS 后端框架）提供了后端能力：目录镜像路由、
dev 模式 `.ts` 直跑热更、`oj build/migrate/server` 发布链。

本需求把两者统一：**开发者只用 ram 四个命令（init/dev/build/preview）即可完成
前后端一体化工程的创建、开发、构建与预览**，oj 作为实现细节被 ram 编排。

## 2. 已确认决策

| # | 决策点 | 结论 |
|---|---|---|
| D1 | 工程目录布局 | 按 PRD 新布局：`modules/src` + `modules/dist`、`api/src` + `api/dist`（src/dist 同级配对） |
| D2 | dev 架构 | 双进程 + 自动刷新：ram devServer 跑前端并反代 `/api` 到 oj 子进程；重建完成经 SSE 推送整页 reload |
| D3 | oj 产物来源 | `oj-v0.1.0.tar.gz` 随 ram 包内置（`vendor/`，纳入 `files`），init 时解压到工程 `bin/` |
| D4 | preview 静态站 | `--app-path` 指 `modules/dist`（完整站点，build 时合并 shell + 模块）；`--api-path` 指 `api/dist` |
| D5 | 整体编排 | 方案 A：ram 作为编排器，统一拉起/回收 oj 子进程与 vite 构建 |
| D6 | oj 证书 | ram 内置一份 dev 专用自签证书（public.pem / cert.jws / private.pem），标注仅本地开发用；生产用 oj 仓库 `tools/oj-cert` 重签 |
| D7 | 后端构建器 | 维持 `oj build`（见 §7 论证），vite 只负责前端模块 |

## 3. 工程布局（ram init 产物）

```text
<name>/
├── bin/                    # 解内置 tar.gz：oj 二进制 + plugins/ + devkit/
├── api/
│   ├── config.yaml         # oj 配置：server.base "/api"、port 9778、sqlite DSN、证书路径
│   ├── config/             # dev 自签证书（D6）
│   ├── src/demo/           # 示例后端模块（manifest.yaml + api.ts）
│   └── dist/               # oj build 产物（ram build 生成）
├── modules/
│   ├── src/demo/           # 示例前端模块（entry.ts + pages/ + locales/）
│   └── dist/               # 完整站点（ram build 合并 shell 产出，见 §5）
├── .claude/skills/oj-api-dev/  # devkit SKILL.md + api-manual.md（init 拷贝）
├── modules.config.ts       # 沿用现有约定
├── package.json            # scripts: dev/build/preview/info
├── tsconfig.json
└── global.d.ts             # 拷自 devkit，oj 全局对象类型提示
```

## 4. ram dev（双进程 + 自动刷新）

```text
ram devServer :5174
  /             → shell index.html（注入 SSE 刷新脚本）
  /assets/*     → shell dist
  /modules*     → modules/dist（watch 重建，300ms 防抖）
  /api/*        → 反代到 http://localhost:<ojPort>（node:http 转发，不引依赖）
  /__ram_reload → SSE 通道（text/event-stream）

bin/oj server :9778（ram 拉起的子进程）
  -c api/config.yaml --api-path api/src   # 无 manifests.yaml → dev/ts 模式，热更为 oj 原生能力
```

启动序列：

1. **Preflight**：`bin/oj` 与 `api/src` 都在 → 全栈模式；缺任一 → 退化前端-only
   模式（`mock/*.mock.mjs` 接管 `/api`，与现状完全一致）并打警告。
2. **拉起 oj 子进程**：端口用正则从 `api/config.yaml` 读 `server.port`（回落 9778，
   不为 YAML 解析引依赖）；oj stdout/stderr 加 `[oj]` 前缀透传；启动即退（证书/DB/
   端口）时透传 stderr 并以非零码退出。
3. **devServer 增量**（复用现有 `dev.ts`，两处改动）：
   - `/api/*` 由 mock 改为反代（仅全栈模式；前端-only 模式维持 mock 行为）；
   - 自动刷新：服务 index.html 时在 `</body>` 前注入 `<script>`，连
     `/__ram_reload`（SSE），收 `reload` 事件即 `location.reload()`；模块重建
     成功后广播，失败不广播（旧产物继续服务，终端报错——延续现有行为）。
4. **退出回收**：SIGINT/SIGTERM 先 kill oj 子进程再退出，不留孤儿占 9778。

有意不做：完整 HMR（react-refresh preamble / dev-runtime 映射）维持设计文档
P5 偏差结论，整页 reload 已覆盖「保存即见效果」；`mock/` 与 oj 不叠加——有 oj
时 `/api` 全部反代，心智模型唯一。

## 5. ram build

1. **后端**（`api/src` 存在时）：
   - `bin/oj build -d api/src -o api/dist`；
   - `bin/oj migrate -c api/config.yaml -d api/dist`（release 迁移门禁 verify 要求
     账本不落后，build 时就绪，preview 才能直接起）。
2. **前端**：`buildModules` 构建 `modules/src` 到临时目录，再合并输出
   `modules/dist` 完整站点：
   - 先拷 shell dist 全量（`index.html`、`assets/`、`versions.json`、favicon 等）；
   - 再写入 `modules.json` 与 `modules/<name>/` 模块产物。
   - 产物自包含、可独立部署，preview 的 `--app-path` 直指它。
3. 无 `api/src` → 跳过后端两步，纯前端工程照常可用。

## 6. ram preview

```bash
bin/oj server -c api/config.yaml \
  --app-path <abs modules/dist> \
  --api-path <abs api/dist>
```

- 一律传绝对路径，避开 oj「相对 config 目录」的解析歧义。
- 启动前 fail-fast：`modules/dist/index.html` 与 `api/dist/manifests.yaml`
  缺一即提示先 `ram build`。

## 7. 后端构建器论证（D7）

不统一用 vite 编译后端。`oj build` 不是 TS 转译器，而是 oj 框架的发布契约：

1. `manifests.yaml` 锁：oj server 靠它判定 release/js 模式（`server_cmd::is_release`）；
2. `routes.js` 路由表 + `.route` 剥离：release 下参数路由以 routes.js 为准；
3. 版本目录聚合 + 结构检查（`--check`：表归属、跨模块 deps、seed 纪律）；
4. `oj migrate` 的迁移账本挂在 dist 产物上。

vite 只能完成其中转译一环，其余产物无法生成，与 oj 运行时契约对不齐。前后端的
一致性在「都只写 JS/TS」这层（oj 的核心卖点），而非同一个构建器。

## 8. 错误处理

| 场景 | 行为 |
|---|---|
| `bin/oj` 缺失 | 人话报错：提示重新 `ram init` 或检查 tar.gz 解压 |
| oj 子进程启动即退（证书/DB/端口） | 透传 oj stderr，ram 非零码退出 |
| devServer 端口占用 | 现有顺延逻辑不变 |
| 模块重建失败 | 终端报错、不广播 reload、旧产物继续服务 |
| tar.gz 平台不符（包内为 mac 二进制/dylib） | 现阶段仅支持 macOS，init 时 `process.platform` 检查并明说 |

## 9. 测试

- **单测**（Vitest，沿用 `packages/cli` 现有测试约定）：
  - init：脚手架产物存在性与关键内容（config.yaml 的 base/port、证书三件套、
    SKILL.md 拷贝、示例模块）；
  - devServer：`/api` 反代与 SSE 注入——用桩 HTTP server 冒充 oj，断言转发与
    `</body>` 注入；
  - build：合并后 `modules/dist` 目录结构断言（index.html / assets /
    versions.json / modules.json / modules/）；
  - preview：spawn 参数断言（绝对路径、--app-path/--api-path 指向）。
- **e2e**（本机可跑，CI 跳过）：tmp 目录 `ram init` → `ram build` → 起 preview
  冒烟，curl `/` 与一条 API 各一次。

## 10. 变更面

- `packages/cli/`：新增 `init.ts` / `preview.ts` / `dev-proxy.ts`（反代 + SSE）/
  `vendor/oj-v0.1.0.tar.gz` / `vendor/dev-cert/`（证书三件套）；
  改 `index.ts`（注册 init/preview）、`dev.ts`（§4 两处增量）、`build.ts`
  （输出目标改为 `modules/dist` 合并站点 + oj 子命令）、`package.json`
  （`files` 加 vendor）。
- 不动 runtime/shell；旧布局工程（playground）由 build/dev 兼容读取——
  布局探测优先级：`modules/src` 存在 → 新布局，否则回退现有 `modules/` + `dist/`。

## 11. 偏差与记录

- PRD 中 `raw build` / `raw preview` 为笔误，按 `ram` 实现。
- oj-cert 不随 tar.gz 发行 → D6 以内置 dev 证书绕过，生产证书另由 oj 仓库工具重签。
- tar.gz 当前仅含 macOS 产物，跨平台分发留待 oj 出多平台包后再议。
