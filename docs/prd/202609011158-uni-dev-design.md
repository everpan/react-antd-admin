# 前后端统一开发工具（uni-dev）设计

> 需求源：`docs/prd/uni-dev.md`。本文是经脑暴确认后的设计方案，实现计划另出。
> 关键决策均已在脑暴中与需求方逐条确认（D1–D7）；2026-09-01 审阅补充 D8–D9
>（对照 oj 二进制 `--help` 与 devkit 手册逐条核实，见 §11 审阅记录）。

## 1. 背景与目标

`@react-antd-module/cli`（ram）目前只覆盖前端模块工程（dev/build/info/merge）。
oj（only-js，Rust 内嵌 V8 的 JS/TS 后端框架）提供了后端能力：目录镜像路由、
dev 模式 `.ts` 直跑热更、`oj build/migrate/server` 发布链。

本需求把两者统一：**开发者只用 ram 四个命令（init/dev/build/preview）即可完成
前后端一体化工程的创建、开发、构建与预览**，oj 作为实现细节被 ram 编排。

## 2. 已确认决策

| # | 决策点 | 结论 |
|---|---|---|
| D1 | 工程目录布局 | 按 PRD 新布局：`modules/src` + `modules/dist`、`api/src` + `api/dist`（src/dist 同级配对） |
| D2 | dev 架构 | 双进程 + 自动刷新：ram devServer 跑前端并反代 `/api` 到 oj 子进程；重建完成经 SSE 推送整页 reload |
| D3 | oj 产物来源 | `oj-v0.1.0.tar.gz` 随 ram 包内置（`vendor/`，纳入 `files`），init 时解压到工程 `bin/` |
| D4 | preview 静态站 | `--app-path` 指 `modules/dist`（完整站点，build 时合并 shell + 模块）；`--api-path` 指 `api/dist` |
| D5 | 整体编排 | 方案 A：ram 作为编排器，统一拉起/回收 oj 子进程与 vite 构建 |
| D6 | oj 证书 | ram 内置一份 dev 专用自签证书（public.pem / cert.jws / private.pem），**有效期 3650 天**，标注仅本地开发用；生产用 oj 仓库 `tools/oj-cert` 重签（证书无绕过开关且 oj-cert 不随包发行，短有效期即时钟炸弹，见 §11） |
| D7 | 后端构建器 | 维持 `oj build`（见 §7 论证），vite 只负责前端模块 |
| D8 | migrate 时机 | `oj migrate` 放 preview（起 server 前），`ram build` 保持零 DB 副作用，对齐 oj 部署公式 `build && migrate && server` |
| D9 | preview SPA 回退 | oj 静态服务无 SPA fallback → preview 记为已知限制（问题分类：与业界不符），oj 侧立项修复后移除（见 §6/§11） |

## 3. 工程布局（ram init 产物）

```text
<name>/
├── bin/                    # 解内置 tar.gz：oj 二进制 + plugins/ + devkit/
├── api/
│   ├── config.yaml         # oj 配置：server.base "/api"、port 9778、sqlite DSN、证书路径；
│   │                       #   不含 auth 段（匿名可调，e2e 冒烟免 token；加 auth: 即启用
│   │                       #   内置 /auth/login|refresh|logout，协议与前端 auth store 对齐）
│   ├── config/             # dev 自签证书（D6）
│   ├── src/demo/           # 示例后端模块（manifest.yaml + api.ts）
│   ├── db.sqlite           # 运行时生成（sqlite DSN 相对 config.yaml 所在目录）
│   └── dist/               # oj build 产物（ram build 生成）
├── modules/
│   ├── src/demo/           # 示例前端模块（entry.ts + pages/ + locales/）
│   └── dist/               # 完整站点（ram build 合并 shell 产出，见 §5）
├── .claude/skills/oj-api-dev/  # devkit SKILL.md + api-manual.md（init 拷贝）
├── modules.config.ts       # 沿用现有约定
├── package.json            # scripts: dev/build/preview/info；依赖清单照搬 playground
│                           #   （cli/shell/runtime + react/antd/typescript 等 devDeps）
├── tsconfig.json
└── global.d.ts             # 拷自 devkit，oj 全局对象类型提示
```

## 4. ram dev（双进程 + 自动刷新）

```text
ram devServer :5174
  /             → shell index.html（注入 SSE 刷新脚本）
  /assets/*     → shell dist
  /modules*     → modules/dist（watch 重建，300ms 防抖）
  /api/*        → 反代到 http://localhost:<ojPort>（node:http 转发，不引依赖）
  /__ram_reload → SSE 通道（text/event-stream）

bin/oj server :9778（ram 拉起的子进程）
  -c <abs api/config.yaml> --api-path <abs api/src>   # 无 manifests.yaml → dev/ts 模式，热更为 oj 原生能力
```

启动序列：

1. **Preflight**：`bin/oj`、`api/config.yaml` 与 `api/src` 都在 → 全栈模式；缺任一 →
   退化前端-only 模式（`mock/*.mock.mjs` 接管 `/api`，与现状完全一致）并打警告。
2. **拉起 oj 子进程**：端口用正则从 `api/config.yaml` 读 `server.port`（回落 9778 时
   告警并提示显式配置——oj 代码默认是 778，正则 miss 说明配置被改动；不为 YAML
   解析引依赖）；`--api-path` 传绝对路径（oj 的命令行相对路径相对 CWD、config 内
   相对路径相对 config 所在目录，双语义易错，统一绝对路径后规则只剩一条，与 §6
   preview 一致）；oj stdout/stderr 加 `[oj]` 前缀透传；拉起后轮询 `{base}/health`
   就绪再打印启动完成（避免 oj 未就绪时浏览器首批 `/api` 请求吃 502，启动即退也由
   轮询暴露）；启动即退（证书/DB/端口）时透传 stderr 并以非零码退出。
3. **devServer 增量**（复用现有 `dev.ts`，三处改动）：
   - `/api/*` 由 mock 改为反代（仅全栈模式；前端-only 模式维持 mock 行为）；
   - 自动刷新：服务 index.html 时在 `</body>` 前注入 `<script>`（index.html 主路径
     与 SPA fallback 两处都要注入），连 `/__ram_reload`（SSE），收 `reload` 事件即
     `location.reload()`；模块重建成功后广播，失败不广播（旧产物继续服务，终端
     报错——延续现有行为）；
   - watch 目标布局感知：新布局 watch `modules/src`，旧布局维持 `modules/`。
     新布局下重建产物写在 `modules/dist`，沿用现 watch `modules/` 会把自身产物当
     源码变更，造成自触发重建循环（审阅发现，见 §11）。
4. **退出回收**：SIGINT/SIGTERM 先 kill oj 子进程再退出，不留孤儿占 9778。

有意不做：完整 HMR（react-refresh preamble / dev-runtime 映射）维持设计文档
P5 偏差结论，整页 reload 已覆盖「保存即见效果」；`mock/` 与 oj 不叠加——有 oj
时 `/api` 全部反代，心智模型唯一；WS 不代理（node:http 不支持 upgrade，oj 的
WS 能力在 ram dev 下不可用，需要时补 upgrade 转发）。

## 5. ram build

1. **后端**（`api/src` 存在时）：
   - `bin/oj build -d <abs api/src> -o <abs api/dist>`；
   - 不跑 migrate（D8）：`oj build` 本身零磁盘副作用，`ram build` 保持零 DB 副作用
     （CI/无 DB 环境可跑），迁移账本由 preview 在起服务前应用（§6）。
2. **前端**：`buildModules` 构建 `modules/src` 到临时目录，再合并输出
   `modules/dist` 完整站点：
   - 先拷 shell dist 全量（`index.html`、`assets/`、`versions.json`、favicon 等）；
   - 再写入 `modules.json` 与 `modules/<name>/` 模块产物。
   - 产物自包含、可独立部署，preview 的 `--app-path` 直指它。
3. 无 `api/src` → 跳过后端构建，纯前端工程照常可用。

## 6. ram preview

```bash
bin/oj migrate -c <abs api/config.yaml> -d <abs api/dist>   # D8：先迁移再起服务
bin/oj server -c <abs api/config.yaml> \
  --app-path <abs modules/dist> \
  --api-path <abs api/dist>
```

- 一律传绝对路径，避开 oj「命令行相对 CWD / config 内相对 config 目录」的双语义歧义
  （含 `-c`，与 §4 dev 一致）。
- 先 `oj migrate` 再 `oj server`：对齐 oj 部署公式 `build && migrate && server`，
  release 的 verify 迁移门禁由 migrate 先行满足。
- 启动前 fail-fast：`modules/dist/index.html` 与 `api/dist/manifests.yaml`
  缺一即提示先 `ram build`。
- **已知限制（D9）**：oj 静态服务无 SPA 回退——`/` 直达与站内跳转可用，history
  路由下刷新/深链接 404（`VITE_ROUTER_MODE` 已烧进预构建 shell，模板改 hash 救不了）。
  待 oj 侧补「GET 未命中 + 路径无扩展名 + Accept: text/html → index.html」后移除本条。

## 7. 后端构建器论证（D7）

不统一用 vite 编译后端。`oj build` 不是 TS 转译器，而是 oj 框架的发布契约：

1. `manifests.yaml` 锁：oj server 靠它判定 release/js 模式（`server_cmd::is_release`）；
2. `routes.js` 路由表 + `.route` 剥离：release 下参数路由以 routes.js 为准；
3. 版本目录聚合 + 结构检查（`--check`：表归属、跨模块 deps、seed 纪律）；
4. `oj migrate` 的迁移账本挂在 dist 产物上。

vite 只能完成其中转译一环，其余产物无法生成，与 oj 运行时契约对不齐。前后端的
一致性在「都只写 JS/TS」这层（oj 的核心卖点），而非同一个构建器。

## 8. 错误处理

| 场景 | 行为 |
|---|---|
| `bin/oj` 缺失 | 人话报错：提示重新 `ram init` 或检查 tar.gz 解压 |
| oj 子进程启动即退（证书/DB/端口） | 透传 oj stderr，ram 非零码退出 |
| devServer 端口占用 | 现有顺延逻辑不变 |
| 模块重建失败 | 终端报错、不广播 reload、旧产物继续服务 |
| tar.gz 平台不符（包内为 mac 二进制/dylib） | 现阶段仅支持 macOS，init 时 `process.platform` 检查并明说 |
| `api/config.yaml` 缺 `server.port`（正则 miss） | 告警回落 9778 并提示显式配置（oj 代码默认 778） |
| oj 未就绪期间的 `/api` 请求 | 反代返回 502；devServer 以 `{base}/health` 轮询，就绪后才打印启动完成 |

## 9. 测试

- **单测**（Vitest，沿用 `packages/cli` 现有测试约定）：
  - init：脚手架产物存在性与关键内容（config.yaml 的 base/port、证书三件套、
    SKILL.md 拷贝、示例模块）；
  - devServer：`/api` 反代与 SSE 注入——用桩 HTTP server 冒充 oj，断言转发与
    两处 `</body>` 注入（主路径 + SPA fallback）；watch 目标断言（新布局
    `modules/src` / 旧布局 `modules/`）；
  - build：合并后 `modules/dist` 目录结构断言（index.html / assets /
    versions.json / modules.json / modules/）；零 DB 副作用断言（不 spawn migrate）；
  - preview：spawn 参数与顺序断言（绝对路径、migrate → server、
    --app-path/--api-path 指向）。
- **e2e**（本机可跑，CI 跳过）：tmp 目录 `ram init` → `ram build` → 起 preview
  冒烟，curl `/` 与一条 API 各一次。

## 11. 偏差与记录

- PRD 中 `raw build` / `raw preview` 为笔误，按 `ram` 实现。
- oj-cert 不随 tar.gz 发行 → D6 以内置 dev 证书绕过，生产证书另由 oj 仓库工具重签；
  内置证书有效期签 **3650 天**（oj 证书无任何绕过开关、宽限期尽拒启且用户无
  自助续期手段，短有效期等于时钟炸弹）。
- tar.gz 当前仅含 macOS 产物，跨平台分发留待 oj 出多平台包后再议。
